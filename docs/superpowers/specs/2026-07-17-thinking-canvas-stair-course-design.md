# 小学数学思维阶梯课程与静思画板设计

**日期：** 2026-07-17

**状态：** 已确认

**适用项目：** InspireEd

**首期范围：** 二至六年级课程总图、数量关系与模型试点、`THINKING_CANVAS` Cell

## 1. 目标

在 InspireEd 现有课程、教案、Cell、课堂会话和过程评价体系内，增加一套以图示思考为核心的小学数学思维课程能力。

本设计同时解决两个问题：

1. 建立二至六年级小学数学思维的阶梯课程总图。
2. 新增独立的“静思画板” Cell，让每名学生经历观察、绘制、支架、修正、总结和反思。

静思画板不是独立应用，也不替代现有协作白板。它是一种个人学习活动，完成后可把典型作品匿名发送到协作白板，进入全班共学。

## 2. 设计原则

1. **课程先行。** 画板能力由真实课程任务决定，不建设脱离课程的通用绘图工具。
2. **个人静思优先。** 学生作品默认私密，提交后教师才能查看内容。
3. **先思后教。** 学生留下第一版思考痕迹后才能打开知识支架。
4. **支架不替代思考。** 支架按需开放，并记录调用层级；后续任务逐步撤出。
5. **过程可追溯。** 保存初稿、关键修改、最终稿、总结和反思，而不只保存答案。
6. **职责隔离。** `THINKING_CANVAS` 保存个人学习作品；`WHITEBOARD` 继续承担课堂分组协作。
7. **最小实现。** 首期复用现有 InspireEd 画板引擎，不直接引入 Obsidian Excalidraw 插件或 React 运行层。

## 3. 课程总体结构

课程暂定名为“**小学数学思维：从画出来到建模型**”。

### 3.1 五级能力阶梯

| 层级 | 能力目标 | 可观察表现 |
|---|---|---|
| L1 观察发现 | 找到条件、差异和规律 | 圈画、标记、估计、提出猜想 |
| L2 图示表达 | 把文字转成图、表和关系 | 线段图、列表、树形图、集合图 |
| L3 方法建模 | 形成稳定且可解释的方法 | 命名方法、说明步骤、连接图与算式 |
| L4 变式比较 | 比较条件改变前后的关系 | 对照、修改模型、解释不变量 |
| L5 迁移创造 | 在陌生情境中选择和组合方法 | 自主选图、一题多解、跨情境迁移 |

### 3.2 六条课程主线

| 主线 | 阶梯内容 | 主要画板表征 |
|---|---|---|
| 观察与规律 | 找规律→周期→数表与日历→等差数列→整数与数列 | 连续格、数表、数轴、变化箭头 |
| 分类与计数 | 枚举→有序列表→树形图→加乘原理→排列组合→容斥 | 分类表、树形图、集合图、路径网格 |
| 数量关系与模型 | 移多补少→和差→和倍/差倍→鸡兔同笼→假设→方程→单位“1”→工程/浓度 | 实物图、线段图、数量表、假设图、关系图 |
| 图形与空间 | 图形分割→周长→面积→平移割补→几何计数→格点→比例模型→组合图形 | 方格纸、辅助线、移动箭头、重叠区域 |
| 行程与变化 | 速度/时间/路程→相遇→追及→环形跑道→火车过桥→流水行船→速度比 | 路线图、时间轴、双线段图、动态位置图 |
| 逻辑与优化 | 排序排除→真假判断→一笔画→操作智巧→统筹→抽屉→最值/染色证明 | 排除表、网络图、步骤图、方案比较表 |

### 3.3 年级定位

| 年级 | 重点 |
|---|---|
| 二年级 | 具体操作、直观画图、简单差量、有序观察 |
| 三年级 | 线段图、列表、树形图、基础应用模型 |
| 四年级 | 方法命名、关系组合、初步符号化 |
| 五年级 | 组合、数论、比例模型、存在性论证 |
| 六年级 | 单位“1”、假设、方程、综合模型迁移 |

年级用于确定起点，不作为锁死路径。学生通过诊断后可以沿方法主线进入更高层级。

## 4. 首个试点：数量关系与模型

首期实现八课，每课建议 25 至 35 分钟。

### 4.1 课程序列

| 课次 | 主题 | 核心理解 | 画板模板 | 主要证据 |
|---|---|---|---|---|
| 1 | 移动为什么要除以2 | 从一边移动一个单位到另一边，差减少两个单位 | 双容器＋可拖拽对象 | 能用图解释差量变化 |
| 2 | 已知和与差怎样画 | 去掉差量后可平均分配 | 双线段图 | 能由图解释和差公式 |
| 3 | 寻找一倍量 | 差倍中的差对应“倍数减1”份 | 份数线段图 | 能识别并解释一倍量 |
| 4 | 全部假设成一种会怎样 | 假设结果与实际结果的差可用于调整 | 动物符号＋腿数表 | 能画出逐次替换的差量 |
| 5 | 同一道题的多种模型 | 列表、假设、方程具有不同适用性 | 三栏方法比较 | 能比较方法而非只报答案 |
| 6 | 从图走向未知数 | 方程是图中数量关系的符号压缩 | 图示—方程双栏 | 能指出方程项与图的对应关系 |
| 7 | 寻找不变量 | 倒推时运算和顺序都要反转 | 正向/反向流程双轨图 | 能逐步解释逆运算 |
| 8 | 陌生情境中的迁移 | 表面不同的问题可能共享同一结构 | 学生自主选模板 | 无方法标签时完成建模和解释 |

### 4.2 单课统一流程

1. 情境导入：Text 或 Image Cell。
2. 静观：阅读、圈画条件、复述目标。
3. 独立绘制：`THINKING_CANVAS` 产生第一版图示。
4. 卡点说明：学生指出理解、方法、表达或计算困难。
5. 分级支架：按需开放注意、表征、方法和步骤支架。
6. 修正提交：保留初稿，生成最终稿。
7. 匿名共学：教师选择典型作品发送到协作白板。
8. 变式迁移：Activity Cell。
9. 总结反思：个人方法总结与共学后反思。

## 5. `THINKING_CANVAS` Cell

### 5.1 职责

`THINKING_CANVAS` 是个人学习单元。它负责：

- 展示思考任务和背景图；
- 加载初始图示模板；
- 提供画笔、对象、文字、连线和基础几何工具；
- 延迟开放分级知识支架；
- 自动保存个人作品；
- 保存初稿、关键稿和最终稿；
- 收集方法总结与反思；
- 支持教师提交后审阅和匿名展示。

它不负责：

- 课堂多人实时协作；
- 小组区域和分组权限；
- AI 自动评分；
- 完整操作回放；
- 通用 Excalidraw 文件编辑。

### 5.2 状态机

```text
NOT_STARTED
  → OBSERVING
  → DRAWING
  → SCAFFOLDED
  → REFLECTING
  → SUBMITTED
```

若教师允许提交后修改，`SUBMITTED` 可显式执行“撤回并修改”；系统保留原提交版本，不能静默覆盖。

### 5.3 教师配置

教师可设置：

- 思考任务和补充说明；
- 题目图片；
- 建议静思时间；
- 空白、线段图、表格、树形图或集合图模板；
- 1 至 4 级知识支架；
- 是否必须填写总结；
- 提交后是否允许修改；
- 典型作品是否匿名展示。

### 5.4 学生流程

1. 学生进入任务，系统创建个人作品。
2. 学生完成观察记录并产生第一笔有效内容。
3. 系统保存初稿并开放支架入口。
4. 学生可以继续独立思考或逐级申请支架。
5. 每次打开支架前保存关键版本。
6. 学生完成画板、方法总结和反思后提交。
7. 提交后进入只读状态。
8. 共学结束后补充共学后反思。

### 5.5 教师流程

教师在课堂中只能看到学生状态、最高支架层级和最后保存时间。未提交作品内容保持私密。

学生提交后，教师可以：

- 查看初稿与终稿；
- 查看支架调用记录；
- 添加反馈；
- 标记典型作品；
- 匿名投屏；
- 将作品快照发送到现有协作白板。

## 6. 数据设计

### 6.1 Cell 配置

`cells.content` 保存任务内容：

```json
{
  "prompt": "鸡兔共有20只，共有56条腿。请用画图的方法说明思路。",
  "instructions": "先观察数量关系，不急着列算式。",
  "prompt_image_url": null,
  "template_type": "segment_diagram",
  "suggested_minutes": 10,
  "scaffolds": [
    {
      "level": 1,
      "title": "观察提示",
      "content": "鸡和兔每只相差几条腿？"
    }
  ]
}
```

`cells.config` 保存行为配置：

```json
{
  "allow_edit_after_submit": false,
  "anonymous_display": true,
  "require_summary": true,
  "autosave_interval_seconds": 15,
  "max_versions": 20
}
```

### 6.2 个人作品表

新增 `thinking_canvas_submissions`：

- `id`
- `cell_id`
- `lesson_id`
- `session_id`，自主学习时允许为空
- `student_id`
- `status`
- `canvas_document`
- `highest_scaffold_level`
- `scaffold_events`
- `method_summary`
- `difficulty_note`
- `reflection`
- `peer_learning_reflection`
- `teacher_feedback`
- `is_featured`
- `submitted_at`
- `created_at`
- `updated_at`

唯一约束为 `(cell_id, student_id, session_id)`。自主学习没有 `session_id` 时，服务层必须使用确定的学习实例标识，避免 SQL `NULL` 唯一约束产生重复作品；具体实现计划中应选择显式 `learning_instance_id` 或条件唯一索引。

### 6.3 版本表

新增 `thinking_canvas_versions`：

- `id`
- `submission_id`
- `version_number`
- `document`
- `reason`：`initial`、`before_scaffold`、`final`、`recovery`
- `created_at`

版本策略：

- 第一笔有效内容保存初稿；
- 自动保存只更新当前作品；
- 打开支架前保存关键版本；
- 提交前保存最终版本；
- 首期最多保留 20 个关键版本。

## 7. 画板引擎策略

### 7.1 首期选择

首期复用 `frontend/public/whiteboard/index.html` 中已有的画笔、便签、连线、图片、缩放和小地图能力，但通过适配层隔离数据与消息协议。

静思画板不能直接复用协作白板的课堂共享状态。建议抽取或建立：

```text
ThinkingCanvasCell
  → DrawingAdapter
      → InspireEdCanvasAdapter（首期）
      → ExcalidrawAdapter（后续可选）
```

### 7.2 Excalidraw 边界

Obsidian Excalidraw 插件不能直接嵌入 Vue 应用。若后续采用 Excalidraw，应使用网页组件或独立 iframe 子应用，并通过 `DrawingAdapter` 交换规范化文档。

首期不引入 React 运行层。只有在试点证明现有画板缺少关键绘图体验时，再评估 Excalidraw 替换。

## 8. 保存、断网和冲突处理

1. 浏览器本地存储保存最近编辑状态。
2. 后端数据库保存正式当前稿和关键版本。
3. 默认每 15 秒自动保存，页面离开和提交前强制保存。
4. 保存失败时保留本地稿，显示非阻塞提示并自动重试。
5. 重连时比较服务端版本和本地更新时间。
6. 两侧都发生修改时创建 `recovery` 版本，不静默覆盖。
7. 提交请求必须幂等；重复点击不能生成两份提交。
8. 提交后默认拒绝写入，除非教师允许显式撤回。

## 9. 权限与隐私

- 学生只能读取和修改自己的作品。
- 教师只能查看自己有权限的课程或课堂中的作品。
- 未提交作品的内容不通过教师普通接口返回。
- 典型作品默认匿名展示。
- 发送到协作白板前移除姓名和用户标识。
- 后端必须校验作品归属，不能依赖前端隐藏。
- 管理员普通教学页面不提供学生作品浏览入口。

## 10. 与现有协作白板衔接

首期采用快照衔接：

1. 教师选择已提交作品。
2. 服务端或前端生成无身份信息的图片快照。
3. 快照作为“静思典型作品”插入指定协作白板。
4. 原个人作品保持不变。

首期不把个人作品转换成可编辑白板元素；该能力只有在课堂实践确认需要后再增加。

## 11. API 边界

实现计划应提供以下能力，具体 URL 遵循项目现有 API 命名规范：

- 创建或获取当前学生作品；
- 保存当前画板；
- 打开支架并原子记录事件；
- 提交作品；
- 撤回作品（配置允许时）；
- 保存总结和反思；
- 教师获取作品状态列表；
- 教师读取已提交作品及版本；
- 教师反馈和典型作品标记；
- 生成匿名快照并发送到协作白板。

## 12. 失败场景

| 场景 | 预期行为 |
|---|---|
| 首次加载失败 | 保留任务页，提供重试，不创建重复作品 |
| 自动保存失败 | 本地保留，提示“尚未同步”，后台重试 |
| 打开支架时保存失败 | 不丢失画板；支架事件与关键版本使用同一事务或可恢复协议 |
| 重复提交 | 返回同一提交结果，不新增记录 |
| 提交后继续写入 | 后端拒绝并返回明确状态 |
| 未提交作品被教师请求 | 返回无权限或仅状态数据 |
| 匿名展示 | 快照和元数据均不包含学生身份 |
| 协作白板不可用 | 个人作品保持不变，可稍后重试发送 |

## 13. 测试策略

### 13.1 后端

- 学生作品归属与教师课程权限测试；
- 唯一学习实例和幂等创建测试；
- 自动保存、关键版本和提交状态机测试；
- 打开支架前版本保存的事务测试；
- 未提交内容不可被教师读取测试；
- 匿名快照不泄漏身份测试；
- 提交后写入拒绝测试；
- 自主学习和课堂会话两种路径测试。

### 13.2 前端

- 第一笔前支架入口禁用；
- 第一笔后初稿保存并开放支架；
- 本地保存与断网恢复；
- 模板加载和五类模板基本操作；
- 提交前总结必填校验；
- 提交后只读；
- 教师状态列表不预加载未提交画板内容；
- 匿名展示流程。

### 13.3 端到端

1. 教师创建试点课程和静思画板。
2. 两名学生分别进入，作品互不可见。
3. 一人无提示完成，一人打开二级支架。
4. 教师只能看到进行状态。
5. 学生提交后教师查看初稿、终稿和支架记录。
6. 教师匿名发送典型作品到协作白板。
7. 学生完成共学后反思。

## 14. 试点成功标准

- 至少 80% 的学生留下有效第一版图示；
- 支架打开前存在独立尝试；
- 同一方法后续课时的支架依赖下降；
- 学生能解释图示、算式与方法之间的关系；
- 第 8 课在隐藏方法名称时仍能完成迁移；
- 教师能利用典型作品组织比较讲评；
- 画板操作没有明显挤占数学思考时间；
- 未出现个人作品越权访问或匿名展示身份泄漏。

## 15. 首期非目标

- 完整二至六年级逐课内容生产；
- AI 自动评分与自动生成支架；
- 多人实时编辑个人静思作品；
- 每一笔操作的完整回放；
- Excalidraw 文件兼容；
- 个人作品转为可编辑协作白板元素；
- 家长端和跨校课程市场。

## 16. 实施顺序

1. 为 `THINKING_CANVAS` 建立类型、默认配置和渲染占位。
2. 建立个人作品、版本模型和权限 API。
3. 抽取现有画板能力，通过适配器支持个人文档。
4. 实现自动保存、支架事件、提交和反思。
5. 实现教师状态列表、提交后审阅和匿名快照。
6. 制作“数量关系与模型”八课试点内容。
7. 运行单元、集成和端到端测试。
8. 用真实课堂数据评估是否需要 Excalidraw 引擎。

## 17. 已确认决策

- 使用独立 `THINKING_CANVAS`，不扩展现有 `WHITEBOARD` 数据模型。
- 默认流程为“个人静思→提交→教师选取→匿名共学→个人反思”。
- 课程先于功能设计。
- 第一版提供完整课程总图和一个详细试点单元。
- 首个试点为“数量关系与模型”。
- 首期复用现有画板能力，Excalidraw 作为后续可替换引擎。
